# feat: Interaction and Brain Visualization

## Overview
Expose the internal state of entity "brains" (neural manifests) and LLM exchanges (prompts/responses) to the user. Provide a global interaction log to track entity behavior across the simulation.

## Problem Frame
Entities act as "black boxes" in the current UI. Users can't see the `CapabilityManifest` generated by the neural network or the raw prompts/responses from the LLM. Interactions like signals are invisible unless specifically looked for in entity details (if at all). (see origin: docs/brainstorms/2026-04-16-interaction-and-brain-visualization-requirements.md)

## Requirements Trace
- R1. Neural State Visualization (Manifest + Activations)
- R2. Raw LLM Exchange Visualization (Full Prompt + Raw Response)
- R3. Global Interaction Log (Signals, Deaths, Births, Movement)
- R4. Real-time updates in the simulation UI

## Scope Boundaries
- Text-based visualization in the existing Quart/FastAPI web interface.
- No changes to neural logic or LLM provider code.

## Key Technical Decisions
- **Redis Stream**: Use `interactions:main` for global logs with a `MAXLEN 1000` to prevent memory exhaustion.
- **Entity Hash**: Store `last_manifest`, `last_activations`, and `last_llm_exchange` in the existing entity hash.
- **Deduplication**: Only log "significant" movement or interactions to keep the log readable.
- **API Optimization**: Use `HMGET` for bulk entity state fetches to exclude large fields (manifests, exchanges) and avoid latency.

## Implementation Units

- [ ] **Unit 1: Storage Layer Updates**
    - **Goal:** Support storing manifest, activations, and LLM exchange data.
    - **Files:**
        - Modify: `simulation/entity.py` (Add fields to `Entity` and `to_storage_dict`)
        - Modify: `storage/redis.py` (Add `RedisInteractionStream`)
        - Modify: `simulation/tick.py` (Update `_load_entity` to handle new fields)
    - **Approach:**
        - Add `last_manifest` (JSON), `last_activations` (JSON), and `last_llm_exchange` (JSON) to `Entity`.
        - `last_llm_exchange` schema: `{"system": str, "user": str, "manifest": dict, "response": str}`.
        - `RedisInteractionStream` should implement `publish_interaction(event_type, source_id, message, extra_data)` with `MAXLEN 1000`.
    - **Verification:** `Entity.to_storage_dict` contains new fields. `RedisInteractionStream` can write and read from Redis.

- [ ] **Unit 2: Capture Logic in TickEngine**
    - **Goal:** Populate new fields and publish interaction events.
    - **Files:**
        - Modify: `simulation/tick.py`
    - **Approach:**
        - In `_process_entity`, store `manifest.model_dump_json()` in `entity.last_manifest`.
        - Store list of neuron activations in `entity.last_activations`.
        - Update `_collect_llm_response` or its caller to capture the full prompt components and raw response, storing it in `entity.last_llm_exchange`.
        - Add `self._stream.publish_interaction(...)` calls in:
            - `_execute_action` for `locomotion` (if distance > 1.0) and `signal_emitter`.
            - `_process_entity` when an entity dies.
            - `tick` when an offspring is born.
    - **Test scenarios:**
        - Entity think tick → `last_manifest`, `last_activations`, and `last_llm_exchange` updated in Redis.
        - Entity signal → entry in `interactions:main` stream.
    - **Verification:** Check Redis keys for live entities and the interaction stream using `redis-cli` or logs.

- [ ] **Unit 3: API Exposure and Optimization**
    - **Goal:** Serve interaction logs and detailed entity state to the frontend efficiently.
    - **Files:**
        - Modify: `api/routes/simulation.py` (Add `GET /interactions`)
        - Modify: `api/routes/entities.py` (Ensure `get_entity` returns new fields)
        - Modify: `web/main.py` (Update `/api/state` to use `HMGET` or separate data fetching)
    - **Approach:**
        - FastAPI `/simulation/interactions` returns the last N events from the stream.
        - **Optimization:** Update `web/main.py` `/api/state` to fetch only small fields (id, age, pos, provider, model) for the list view.
        - Quart `/api/state` remains minimal; UI will poll interactions separately.
    - **Verification:** `curl http://localhost:8000/simulation/interactions` returns JSON list of events. `/api/state` response is small.

- [ ] **Unit 4: UI Visualization and Interaction Log**
    - **Goal:** Show the new data in the web browser with proper layout and controls.
    - **Files:**
        - Modify: `web/templates/index.html`
    - **Approach:**
        - Add a `div` for the interaction log (bottom of page, collapsible, auto-scroll).
        - Add log controls: **Pause** button and **Filter by ID** (click entity in log to filter).
        - Add empty state message ("Waiting for interactions...") and loading indicators.
        - Update side panel to use **tabs or accordions** for "Neural State" and "Last LLM Exchange" to manage vertical space.
        - Implement `pollInteractions` in JS with client-side capping (keep only last 100 in DOM).
    - **Verification:** View simulation in browser, see the log filling up, select entity and see brain/LLM details in tabs.

## System-Wide Impact
- **Redis Memory:** `MAXLEN 1000` limits stream growth. LLM exchanges are large but stored per-entity (N entities).
- **API Performance:** `HMGET` optimization prevents overview list from lagging.
- **Frontend Performance:** Client-side DOM capping for the log prevents memory leaks in long sessions.

## Risks & Dependencies
- **LLM Rate Limits:** More detailed logging doesn't affect rate limits but might increase latency if not handled async (already async).
- **Format Consistency:** Ensure `AgentOutput` parsing doesn't break if LLM response format changes slightly (already robust).
